# 严格等距根因修复计划

## 目标

- 把最上弦到指板上边界、最下弦到指板下边界的距离，收口为严格的 `0.5 * stringLaneHeight`。
- 彻底移除当前导致“额外上下留白”的旧垂直语义，而不是继续调默认参数。
- 保持现有 `displayState -> configuration -> geometry -> platform view` 的职责边界不变。

## 已确认根因

- [NoteMaster_Ver_1/Shared/Fretboard/FretboardConfiguration.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardConfiguration.swift) 里当前公式仍把 `stringEdgeInsetRatio` 计入 `drawingHeight`：`drawingHeight = stringBandHeight / (1 - 2 * stringEdgeInsetRatio)`。
- [NoteMaster_Ver_1/Shared/Fretboard/FretboardGeometry.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardGeometry.swift) 的 `makeStringBandRect()` 又按 `stringEdgeInsetRatio` 对 `drawingRect` 做了二次纵向内缩。
- 这两层叠加后，当前实际变成：`边界到最外弦中心 = edgeInset + 0.5 * laneHeight`，而不是严格半个 lane。

## 实施步骤

### 1. 重定义配置层垂直真相

- 在 [NoteMaster_Ver_1/Shared/Fretboard/FretboardConfiguration.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardConfiguration.swift) 中移除 `stringEdgeInsetRatio` 对垂直公式的参与。
- 把 `drawingHeight(forStringCount:)` 收口为 `stringBandHeight(forStringCount:)`，即弦列总高直接等于 `stringCount * stringLaneHeight`。
- `preferredHeight(forStringCount:)` 继续只由 `drawingHeight` 和 `verticalInsetRatio` 派生。
- `stringEdgeInsetRatio` 从 `LayoutMetrics` 删除，避免保留一个已失效但仍可误调的字段。

### 2. 让几何层与新真相完全一致

- 在 [NoteMaster_Ver_1/Shared/Fretboard/FretboardGeometry.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardGeometry.swift) 中让弦列垂直区域直接等于 `drawingRect`。
- `makeStringBandRect()` 改成不再纵向内缩，或直接删除并由 `drawingRect` 取代其语义。
- `stringColumnRect`、`stringYPositions`、`stringSpacing` 自动继承新规则，使最外弦中心到边界稳定为 `0.5 * stringLaneHeight`。
- 同步清理/更新当前新增的诊断字段与日志，避免继续输出已删除的 `edgeRatio` 语义。

### 3. 校准受垂直参考变化影响的渲染依赖

- 检查 [NoteMaster_Ver_1/Shared/Fretboard/FretboardLayer.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardLayer.swift) 中 marker 的视觉结果，因为 `markerDiameter` / `markerDoubleDotOffset` 的参考高会从“较短弦带”变成“完整弦列高度”。
- 检查 [NoteMaster_Ver_1/Shared/Fretboard/NoteNameContentProvider.swift](NoteMaster_Ver_1/Shared/Fretboard/NoteNameContentProvider.swift) 的 badge 是否仍保持可读；逻辑预计无需重写，但要确认最外弦更贴近边界后不会出现视觉裁切。
- 只在验证确实失衡时，再微调 `markerDiameterRatio` / `doubleMarkerOffsetRatio` / badge 比例；不回退几何真相。

### 4. 平台链路验证与诊断清理

- 复核 [NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift](NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift) 和 [NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift](NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift) 现有日志钩子是否仍适合验证期使用。
- 验证通过后，将这次用于定位问题的布局诊断日志删除，或至少收敛为 `DEBUG` 条件编译，避免长期污染控制台。
- 平台 `FretboardView` 预期不需要引入任何新公式，继续只消费 `configuration.preferredHeight`。

### 5. 全链路回归验证

- 静态检查：覆盖配置层、几何层、badge、layer、双平台 view、双平台 controller。
- 数值验证：`guitar6 / bass4 / bass5` 下确认 `topEdgeToCenter == bottomEdgeToCenter == lane / 2`。
- 行为验证：确认 `stringSpacing` 仍稳定、badge 尺寸可读、marker 视觉位置合理、`hitTest` 在最上弦/最下弦仍正确。
- 平台验证：确认 `intrinsicContentSize.height` 与派生后的 `preferredHeight` 一致，切换乐器后高度仍能自动刷新。

## 预期结果

- 最外弦到上下边界不再大于弦间距，而是严格等于半个 lane。
- 共享配置/几何链路中不再存在 `stringEdgeInsetRatio` 这层旧垂直真相。
- 视觉上若有变化，只通过 marker/badge 比例微调解决，不再把额外边距重新加回几何模型。
