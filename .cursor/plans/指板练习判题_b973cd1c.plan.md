# 指板练习判题计划

## 目标

在不污染现有 `FretboardView` 命中职责的前提下，新增一条共享练习链路：`FretboardHitResult` -> 共享音高解析 -> 共享练习状态 -> 平台控制器控制台输出。当前阶段只做控制台闭环，不引入额外 UI，但接口设计要为后续显示目标音保留扩展点。

```mermaid
flowchart LR
    fretboardView["指板视图"] --> hitResult["命中结果 FretboardHitResult"]
    hitResult --> platformVC["平台控制器"]
    platformVC --> pitchResolver["共享音高解析"]
    pitchResolver --> trainerState["共享练习状态"]
    trainerState --> consoleOutput["控制台输出"]
```



## 阶段 1：收口 `cell -> pitch` 的共享真相

- 在 [InstrumentTuning.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Fretboard/InstrumentTuning.swift) 增加 `stringIndex + fret -> NotePitch` 的统一出口，复用已有 `openStringPitch(for:)` 与 `NotePitch.advanced(by:)`。
- 在 [FretboardConfiguration.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Fretboard/FretboardConfiguration.swift) 增加薄封装，补上 `stringIndex` 和 `fretRange` 合法性校验，作为页面侧唯一调用入口。
- 顺手让 [NoteNameContentProvider.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Fretboard/NoteNameContentProvider.swift) 改为走这条共享解析链路，消除当前标签渲染与点击判题两套潜在重复逻辑。
- 判题比较以 `PitchClass` 为准，不比较字符串；因此 `C#` 与 `C` 天然判为不相同。

关键依据：当前标签链路已经证明映射公式是 `openPitch.advanced(by: fret)`，只是还没被抽成共享出口。

## 阶段 2：建立共享练习状态机

- 在 `Shared/Fretboard` 下新增一个练习状态文件，建议命名为 `FretboardTrainer.swift` 或 `FretboardPracticeSession.swift`，承载纯逻辑，不放进 `Shared/Controls`。
- 该状态机至少包含：当前目标自然音、自然音候选集 `C D E F G A B`、接收一次点击后的判题方法、答对后生成下一题的推进逻辑。
- 输入使用共享类型：`FretboardHitResult`、`FretboardConfiguration`；输出建议是结构化结果，而不是直接 `print`，例如：目标音、点击音、是否命中有效格、是否正确、是否切题。
- 只在有效点击上判题，优先只消费 `.ended` 事件，避免拖动过程连续刷日志。

建议接口形状：

- `FretboardConfiguration.notePitch(for cell: FretboardCell) -> NotePitch?`
- `TrainerState.handle(hit:configuration:) -> EvaluationResult?`

## 阶段 3：在双平台控制器接入 trainer

- 在 [iOSViewController.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift) 与 [macOSViewController.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift) 新增 trainer state 持有点。
- 保持现有 `fretboardView.onRawEvent = { hitResult in ... }` 接线方式不变，但把当前 `debugSummary` 调试打印升级为：
  - 过滤非 `.ended` 事件
  - 过滤 `cell == nil` 的无效点击
  - 调用 shared trainer 判题
  - 输出目标音 / 点击音 / 是否正确 / 是否生成下一题
- 初始题目在控制器加载后创建一次；答错不换题，答对才随机到下一题。
- 这一步仍然不改 `iOSFretboardView.swift` / `macOSFretboardView.swift` 的职责边界，它们继续只产出 raw hit。

## 阶段 4：补齐验证与回归清单

- 在 [FretboardValidation.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Fretboard/FretboardValidation.swift) 增加两类 shared 校验：
  - `cell -> pitch` 解析正确性，覆盖空弦与普通品位
  - 自然音判题规则，确认 `C` 命中 `C` 为真，`C#` 命中 `C` 为假
- 扩展现有 `manualChecklist(for:)`，加入“随机目标音练习流程”的手工验证项，确保 iOS / macOS 都能回归。
- 如果验证 runner 不适合承载状态机随机性，就把随机源抽成可注入策略，使 shared 逻辑可稳定验证。

## 阶段 5：为后续 UI 扩展留接口，但不在本阶段实现

- 不把目标音显示状态塞进 [FretboardDisplayState.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Controls/FretboardDisplayState.swift)，避免把练习业务和展示配置耦死。
- 控制器只需保留一个可读取的当前目标音属性；未来如果要显示 UI，可以在 `fretboardHostView` 或其同级 overlay 上加标签，不需要回改 `FretboardView` 的 API。
- 这一阶段只做接口预留和命名收口，不提前引入 UI 复杂度。

## 验收标准

- 点击任一有效格子时，能解析出对应 `PitchClass`，且解析逻辑在 shared 层只有一份真相。
- 目标音只从 `C D E F G A B` 中随机。
- 命中相同自然音时输出正确，并立即切到下一题。
- 命中错误音或升降号音时输出错误，且保留当前题目。
- iOS 与 macOS 走同一套 trainer/shared 逻辑，平台层只负责接线与打印。
