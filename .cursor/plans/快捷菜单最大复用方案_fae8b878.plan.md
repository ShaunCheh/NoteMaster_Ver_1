# 快捷菜单最大复用方案

## 总体目标

在不复用现有 `settingsContainerView` modal 壳层的前提下，新增一套“右侧快捷栏 + 左侧独立快捷窗体”的快捷访问系统，并最大化复用现有 settings 的共享导航、面板快照和页面构建能力。

## 架构结论

- 共享层继续以 [Shared/Controls/SettingsPanelStateContext.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Controls/SettingsPanelStateContext.swift) 为状态真相。
- 页级快捷优先复用 [Shared/Controls/SettingsNavigationModel.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Controls/SettingsNavigationModel.swift) 中的 `SettingsRouteID` 与 `SettingsNavigationModel.reconciledPath(_:)`。
- 行级快捷优先复用 [Shared/Controls/SettingsPanelModel.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Controls/SettingsPanelModel.swift) 中的 `SettingsRowID`，不直接持久化具体 `SettingsChoiceItem`。
- 平台层新增独立快捷窗体外壳，但内部尽量复用 [Platform/iOS/Controls/iOSSettingsNavigatorView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsNavigatorView.swift)、[Platform/macOS/Controls/macOSSettingsNavigatorView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsNavigatorView.swift) 和现有 settings panel/page 视图。
- 拖拽不走系统 drag/drop，采用与当前项目风格一致的自定义 direct-manipulation，平台分实现、共享层收口状态。

## 分阶段计划

### 阶段 0：收口契约与复用边界

#### 目标

- 把“什么能收藏、收藏后如何打开、何时降级”在共享层契约上一次性定清楚，避免后续平台层先写 UI 再反向补模型。

#### 范围

- 明确快捷项只支持两类目标：
  - `route`：导航节点
  - `row`：表单行
- 明确不支持的目标：
  - `SettingsActionID`
  - `SettingsChoiceItem`
  - `SettingsPositionFilterItem`
- 明确 route 快捷与 row 快捷的打开语义：
  - route 快捷：打开可导航窗体
  - row 快捷：打开单页表单窗体

#### 主要改动点

- 梳理以下文件中的稳定标识和降级能力：
  - [Shared/Controls/SettingsNavigationModel.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Controls/SettingsNavigationModel.swift)
  - [Shared/Controls/SettingsPanelModel.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Controls/SettingsPanelModel.swift)
  - [Shared/Controls/SettingsNavigationSnapshotBuilder.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Controls/SettingsNavigationSnapshotBuilder.swift)

#### 阶段产物

- 一套稳定的快捷项契约：
  - `QuickAccessItemID`
  - `QuickAccessOpenTarget`
  - route/row 的降级规则

#### 风险

- route 和 row 混在一个快捷栏里后，如果契约没提前钉死，后续“排序、删除、打开、恢复”都会变成平台层临时判断。

#### 验收口径

- 任何一个快捷项都能映射到唯一的共享层标识。
- 对动态消失的 route/row 都有明确降级策略，不会出现“打开空页”。

### 阶段 1：共享 QuickAccess 模型与内容投影

#### 目标

- 先完成无平台依赖的共享层模型，让快捷栏的数据源、去重规则、排序规则、删除规则、打开目标都在共享层闭环。

#### 范围

- 新增 `QuickAccessItemID`
- 新增 `QuickAccessItem`
- 新增 `QuickAccessState`
- 新增 `QuickAccessContentBuilder`

#### 主要改动点

- 共享层新增 `Shared/Controls/QuickAccess*`
- 复用以下共享 builder：
  - [Shared/Controls/SettingsPanelSnapshotBuilder.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Controls/SettingsPanelSnapshotBuilder.swift)
  - [Shared/Controls/SettingsNavigationSnapshotBuilder.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Controls/SettingsNavigationSnapshotBuilder.swift)

#### 设计要求

- `QuickAccessItemID` 必须同时支持：
  - `route(SettingsRouteID)`
  - `row(SettingsRowID)`
- `QuickAccessItem` 必须预留：
  - `iconName`
  - `title`
  - `subtitle`
  - 当前阶段 `title/subtitle` 仅做元数据，不在快捷栏中展示
- `QuickAccessState` 必须提供：
  - 去重添加
  - 删除
  - 重排
  - 当前打开项
  - 当前是否选择态

#### 阶段产物

- 一套纯共享层的快捷域模型
- 一套 route/row 到“快捷窗体内容”的投影函数

#### 风险

- row 快捷如果直接复用现有 route，将会把不存在的深层页硬塞给 navigator，导致后续状态错乱。

#### 验收口径

- 对任意 `QuickAccessItemID`，共享层都能回答：
  - 是否还能打开
  - 打开后是 navigator 还是单页 form
  - 标题/图标/唯一键是什么

### 阶段 2：给现有 settings 菜单加入选择态

#### 目标

- 让现有 settings 菜单能安全进入“可收藏选择态”，同时保持原导航/点击行为不被破坏。

#### 范围

- 在 settings 容器右下角新增 `pin` 入口
- index 页的 route item 新增 handle
- panel 页的非选项 row 新增 handle
- 原点击行为保留

#### 主要改动点

- [Platform/iOS/Controls/iOSSettingsContainerView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsContainerView.swift)
- [Platform/macOS/Controls/macOSSettingsContainerView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsContainerView.swift)
- [Platform/iOS/Controls/iOSSettingsIndexPageView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsIndexPageView.swift)
- [Platform/macOS/Controls/macOSSettingsIndexPageView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsIndexPageView.swift)
- [Platform/iOS/Controls/iOSSettingsPanelView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsPanelView.swift)
- [Platform/macOS/Controls/macOSSettingsPanelView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsPanelView.swift)

#### 设计要求

- `pin` 开关只改变“选择态”，不改变现有 `isSettingsPresented`
- handle 只挂在：
  - `SettingsRouteItem`
  - `SettingsRow`
- handle 不挂在：
  - choice item 子按钮
  - segmented control 的 segment
  - position filter option 子项

#### 阶段产物

- settings 进入/退出选择态
- 选择态下 route/row 都有拖拽入口

#### 风险

- 如果 handle 的命中区域吞掉原有点击，会破坏“仍可进入二级页面”的需求。

#### 验收口径

- 选择态下点击正文仍按原逻辑工作。
- 只有拖 handle 才进入快捷收藏流程。

### 阶段 3：右侧快捷栏与左侧独立窗体外壳

#### 目标

- 先把“右侧栏 + 左侧窗体”的几何和视图层级建立出来，不急着打通拖拽和内容。

#### 范围

- 新增右侧快捷栏视图
- 新增左侧独立快捷窗体视图
- 在根 VC 统一管理显隐和层级

#### 主要改动点

- [Platform/iOS/iOSViewController.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift)
- [Platform/macOS/macOSViewController.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift)
- 新增：
  - `Platform/iOS/Controls/iOSQuickAccessBarView.swift`
  - `Platform/iOS/Controls/iOSQuickAccessContainerView.swift`
  - `Platform/macOS/Controls/macOSQuickAccessBarView.swift`
  - `Platform/macOS/Controls/macOSQuickAccessContainerView.swift`

#### 设计要求

- 快捷栏：
  - 位于右侧
  - 垂直居中
  - 当前仅显示图标
  - 底层保留文字元数据能力
- 快捷窗体：
  - 位于快捷栏左侧
  - 是独立壳层
  - 不带全屏 backdrop
  - 与现有 settings modal 互不复用外壳

#### 阶段产物

- 右侧快捷栏空壳
- 左侧快捷窗体空壳
- 控制器中统一的快捷系统展示状态

#### 风险

- 现有 `settingsContainerView` 是最后 `addSubview` 的全屏 overlay；如果快捷栏/快捷窗体层级没设计清楚，会被现有 settings 全部盖住。

#### 验收口径

- 快捷栏和快捷窗体在 iOS/macOS 上都能稳定贴边布局。
- settings modal 与快捷系统的层级关系有统一规则。

### 阶段 4：自定义拖拽、投放、排序与删除

#### 目标

- 完成从 handle 开始，到投放进快捷栏，再到栏内排序和删除的完整交互闭环。

#### 范围

- 自定义拖拽会话
- 跟手预览图标
- 进入快捷栏的投放高亮
- 栏内重排
- 删除交互

#### 主要改动点

- `iOSViewController` / `macOSViewController` 持有拖拽会话状态
- `iOSQuickAccessBarView` / `macOSQuickAccessBarView` 提供：
  - 投放命中反馈
  - 插入位置反馈
  - 删除入口
- 可参考钢琴 direct-manipulation 分层：
  - [Shared/Piano/PianoInteractionReducer.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Piano/PianoInteractionReducer.swift)

#### 设计要求

- 拖拽开始后立即关闭 settings modal
- 跟手图标与目标 item 的 icon 元数据一致
- 进入快捷栏区域时显示“可添加/可重排”反馈
- 同一 item 再次投放只触发去重更新，不产生重复项

#### 阶段产物

- 可添加
- 可重排
- 可删除

#### 风险

- 当前工程没有通用 drag/drop 基建，iOS/macOS 必然平台分实现。
- 如果命中测试只写在子视图内，跨出 settings 关闭后容易丢失拖拽状态。

#### 验收口径

- 从 settings handle 拖到快捷栏可稳定收藏。
- 快捷栏内项目可重排、可删除、不可重复。

### 阶段 5：打通 route 快捷与 row 快捷的打开行为

#### 目标

- 让快捷栏真正能打开内容，而不是只存图标。

#### 范围

- route 快捷打开完整 navigator
- row 快捷打开单页 form
- 保持现有 settings event 回写链路

#### 主要改动点

- 复用：
  - [Platform/iOS/Controls/iOSSettingsNavigatorView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsNavigatorView.swift)
  - [Platform/macOS/Controls/macOSSettingsNavigatorView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsNavigatorView.swift)
  - [Platform/iOS/Controls/iOSSettingsPanelView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsPanelView.swift)
  - [Platform/macOS/Controls/macOSSettingsPanelView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsPanelView.swift)

#### 设计要求

- route 快捷：
  - 用 `SettingsNavigationModel` + 初始路径打开
  - 必须走 `reconciledPath(_:)` 兜底
- row 快捷：
  - 直接展示单页 `SettingsPanelModel`
  - 不伪造不存在的 route
- 两种快捷打开后都必须继续复用现有 `SettingsPanelEvent` 回写控制器状态

#### 阶段产物

- 点击 route 快捷可进入二级导航
- 点击 row 快捷可直接编辑该设置项

#### 风险

- route 快捷和 row 快捷若共用同一打开路径而不分流，会让 row 快捷在动态页面下失真。

#### 验收口径

- `Page` 这类快捷项可继续 push/pop。
- `Layout > Viewport Height` 这类快捷项可直接打开单页 slider，并正确回写状态。

### 阶段 6：验证、回归与记录

#### 目标

- 把共享层逻辑和平台层关键交互都补齐验证，避免后面每次调 UI 都回归。

#### 范围

- 共享层验证
- 平台层手工回归
- 改动记录

#### 主要改动点

- 在 `Shared/Controls` 下补快捷项相关 validation
- 扩展现有 settings/navigation validation 覆盖：
  - route 快捷降级
  - row 快捷存在性
  - 去重/排序/删除规则
- 需要的话补一份 commit 记录到 `commit_records`

#### 阶段产物

- 自动化校验覆盖关键共享规则
- 一份明确的双平台手工回归清单

#### 风险

- 如果只测共享层，不测平台拖拽和 hitTest，最容易在 iOS/macOS 之间出现行为分叉。

#### 验收口径

- 共享层去重、重排、降级逻辑可验证。
- iOS/macOS 上以下链路都稳定：
  - 进入选择态
  - 拖拽开始关闭 settings
  - 投放成功
  - 栏内重排
  - 删除
  - route 快捷打开
  - row 快捷打开

## 推荐执行顺序
