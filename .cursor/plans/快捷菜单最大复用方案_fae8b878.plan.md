# 快捷菜单最大复用方案

## 目标

在 `iOSViewController` / `macOSViewController` 根视图上新增一套独立于现有 settings modal 的快捷访问系统：右侧快捷栏负责展示用户收藏的设置入口，点击后在其左侧弹出独立窗体；快捷窗体内部复用现有 settings 的导航/表单能力，但不复用现有 `settingsContainerView` 的 backdrop + 居中卡片外壳。

## 现有可复用锚点

- 共享导航图已经收口到 [Shared/Controls/SettingsNavigationModel.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Controls/SettingsNavigationModel.swift)：优先复用 `SettingsRouteID`、`SettingsPageModel`、`SettingsNavigationModel.reconciledPath(_:)`。
- 共享面板快照已经收口到 [Shared/Controls/SettingsPanelModel.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Controls/SettingsPanelModel.swift) 与 [Shared/Controls/SettingsPanelSnapshotBuilder.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Shared/Controls/SettingsPanelSnapshotBuilder.swift)：行级快捷应基于 `SettingsRowID`，不要直接绑定 `SettingsChoiceItem`。
- 平台导航视图已经分离成 [Platform/iOS/Controls/iOSSettingsNavigatorView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsNavigatorView.swift) / [Platform/macOS/Controls/macOSSettingsNavigatorView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsNavigatorView.swift)：route 级快捷窗体优先复用它们。
- 平台表单行已经按 `SettingsRow` 类型拆分在 [Platform/iOS/Controls/iOSSettingsPanelView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsPanelView.swift) / [Platform/macOS/Controls/macOSSettingsPanelView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsPanelView.swift)：选择态下的 `handle` 适合加在 row 容器层，不要深入 choice item 子按钮。
- 现有 settings 壳层 [Platform/iOS/Controls/iOSSettingsContainerView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsContainerView.swift) / [Platform/macOS/Controls/macOSSettingsContainerView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/NoteMaster_Ver_1/NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsContainerView.swift) 是全屏 backdrop + 居中卡片，不应直接拿来做快捷窗体，但其 header/navigation host 组织方式可以参考。

## 架构方案

- 新增共享快捷标识与状态：在 `Shared/Controls` 下定义 `QuickAccessItemID`（桥接 `SettingsRouteID` / `SettingsRowID`）、`QuickAccessItem`、`QuickAccessState`、`QuickAccessSelectionState`，支持去重、排序、删除与图标/文字元数据。
- 新增共享投影层：在 `Shared/Controls` 下新增 `QuickAccessContentBuilder`，输入 `SettingsPanelStateContext + QuickAccessItemID`，输出“快捷窗体应展示什么”：
  - route 项：复用 `SettingsNavigationSnapshotBuilder.makeModel(from:)`，并带初始 route path。
  - row 项：从 `SettingsPanelModel` 中抽出目标 `SettingsRow` 及其所属 `SettingsSection`，构造单页 form 快照。
- 新增平台快捷栏视图：分别新增 `iOSQuickAccessBarView` / `macOSQuickAccessBarView`，只负责右侧栏展示、选中态、重排占位、删除入口与投放高亮。
- 新增平台快捷窗体视图：分别新增 `iOSQuickAccessContainerView` / `macOSQuickAccessContainerView`，作为根 VC 的 sibling，贴着快捷栏左侧显示；内部可复用 navigator 或 panel，但外壳是新的轻量窗体，不带全屏遮罩。
- 扩展现有 settings UI 为“选择态”：
  - 在 `settingsContainerView` 右下角加入 pin 按钮。
  - 为 `SettingsIndexPageView` 的 route button 和 `SettingsPanelView` 的非选项 row 增加 handle wrapper。
  - 保留原有点击进入二级页面/操作行为，handle 仅承担拖拽入口。
- 平台拖拽采用自定义 direct-manipulation：不引入系统 drag/drop；在 `iOSViewController` / `macOSViewController` 维护拖拽会话、跟手预览、投放命中与结束回调，参考钢琴拖拽的“平台事件 + 共享状态”分层，但不直接复用 `PianoInteractionReducer`。

## 关键实现边界

- 收藏对象只允许“导航节点和表单行”，不允许具体 choice item；因此 `QuickAccessItemID` 不应直接包含 `SettingsActionID`。
- route 快捷点击后应保留现有导航体验；row 快捷点击后打开单页设置窗体，不强行伪造不存在的 route。
- `SettingsNavigationModel.reconciledPath(_:)` 应作为 route 快捷的兜底规范，避免 trainer/layout 等动态条件变化后快捷项失效崩溃。
- 快捷栏与 settings modal 的显隐要由 `*ViewController` 统一协调；拖拽开始时关闭 settings modal，但快捷窗体状态独立维护。

## 验证重点

- 共享层验证：快捷项去重、排序、删除、route 重定位、row 定位与动态隐藏时的降级。
- 平台交互验证：pin 进入/退出选择态、handle 拖拽时 settings 关闭、进入快捷栏高亮、快捷窗体贴边显示、route 快捷仍可 push/pop、row 快捷操作后状态正确回写。
- 手工回归需覆盖 iOS/macOS 两端，因为拖拽与 hitTest 必然是平台分实现。
