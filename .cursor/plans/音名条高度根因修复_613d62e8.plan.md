# 音名条高度根因修复计划

## 目标

- 在 `fretboard -> naturalNoteStrip` 的纵向场景里，解决下方音名按钮区域被按 pane 高度拉伸的问题。
- 保留 `verticalHostHeightRatio` 作为上方 `fretboard` 的目标高度语义；下方 `naturalNoteStrip` 改为按内容高度收缩，只有空间不足时才让上方让步。
- 让上下区域与当前可视 viewport 对齐，避免再由 descendant 约束把整页内容撑高。

## 现状根因

- 共享场景契约 [NoteMaster_Ver_1/Shared/Exercise/ExerciseScene.swift](NoteMaster_Ver_1/Shared/Exercise/ExerciseScene.swift) 里的 `ExerciseSceneSplitChild` 只有 `weight`，没有 `fit-content` 之类的尺寸语义；纵向 split 只能按比例切 pane。
- 共享编排 [NoteMaster_Ver_1/Shared/Exercise/ExerciseCompositionPolicy.swift](NoteMaster_Ver_1/Shared/Exercise/ExerciseCompositionPolicy.swift) 在 `makeMainSceneNode()` 里把 `fretboardToNaturalNoteStrip` 的上下主布局生成成默认 `1:1` 的 vertical split，下方 strip 没有内容高度信息。
- 平台渲染 [NoteMaster_Ver_1/Platform/iOS/Exercise/iOSExerciseSceneRenderer.swift](NoteMaster_Ver_1/Platform/iOS/Exercise/iOSExerciseSceneRenderer.swift) 和 [NoteMaster_Ver_1/Platform/macOS/Exercise/macOSExerciseSceneRenderer.swift](NoteMaster_Ver_1/Platform/macOS/Exercise/macOSExerciseSceneRenderer.swift) 的 `renderSplit()` 只会按 `weight` 分高；`embed()` 又把 surface view 上下四边钉死到 host，导致 `naturalNoteStripView` 被整块拉伸。
- 同一时间，renderer 还通过 `rebuildVerticalFretboardHostHeightConstraint()` 用 `safeAreaHeightAnchor * verticalHostHeightRatio` 给 `fretboardHostView` 额外定高，形成与 split 分高并存的第二套高度真相。
- 控制器 [NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift](NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift) 和 [NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift](NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift) 当前没有把 `sceneContainerView` 固定成 viewport 高度，scroll view 允许 scene 被内部约束继续撑高。

## 修改方案

### 1. 扩展 shared scene contract，显式表达 split child 的尺寸策略

- 在 [NoteMaster_Ver_1/Shared/Exercise/ExerciseScene.swift](NoteMaster_Ver_1/Shared/Exercise/ExerciseScene.swift) 为 `ExerciseSceneSplitChild` 增加尺寸策略，例如 `fill` / `fitContent`。
- 保留现有 `weight` 语义给 `fill` child 使用，避免破坏现有 `sideBySide`、`threePane`、`docked accessory` 等按比例布局路径。
- 只为 vertical split 引入 `fitContent` 的运行时意义，horizontal split 先继续走现有比例模型。

### 2. 在 shared composition policy 中把 `naturalNoteStrip` 标记为内容驱动高度

- 在 [NoteMaster_Ver_1/Shared/Exercise/ExerciseCompositionPolicy.swift](NoteMaster_Ver_1/Shared/Exercise/ExerciseCompositionPolicy.swift) 的 `makeMainSceneNode()` 中，对 `compositionPreset == .fretboardToNaturalNoteStrip` 且 `layoutPreset == .stacked` 的下方 `naturalNoteStripAnswer` child 标记为 `fitContent`。
- 对 vertical accessory split 中的 `naturalNoteStripAccessory` 评估是否同步标记为 `fitContent`；默认建议一并处理，保持 strip 在“主 answer 区”和“accessory 区”两条 vertical 路径上的一致行为。
- `piano` 和其它 pane 继续保持 `fill + weight`，避免这次改动扩散到非问题区域。

### 3. 重写双平台 renderer 的 vertical split 高度分配逻辑

- 在 [NoteMaster_Ver_1/Platform/iOS/Exercise/iOSExerciseSceneRenderer.swift](NoteMaster_Ver_1/Platform/iOS/Exercise/iOSExerciseSceneRenderer.swift) 和 [NoteMaster_Ver_1/Platform/macOS/Exercise/macOSExerciseSceneRenderer.swift](NoteMaster_Ver_1/Platform/macOS/Exercise/macOSExerciseSceneRenderer.swift) 的 `renderSplit()` 中，区分 `fill` child 与 `fitContent` child。
- `fitContent` child：host 高度由 embedded view 的 intrinsic/fitting size 决定，不再参与兄弟间的比例拉伸。
- `fill` child：继续用 `weight` 在剩余高度里分配比例。
- 对 “上 `fretboard` + 下 `naturalNoteStrip`” 这类 mixed vertical split，先结算 strip 的内容高度和 split spacing，再让 `fretboard` 吃剩余空间。
- `embed()` 继续负责把具体 surface view 装进 host，但不再假设所有 vertical child 都必须被比例拉满。

### 4. 把 `verticalHostHeightRatio` 从“全局 safe area 硬定高”改成“slot-local 目标高度语义”

- 在两个平台 renderer 中，调整 `rebuildVerticalFretboardHostHeightConstraint()` / `updateFretboardLayoutModeConstraints()`：不要再在 mixed vertical split 里用 `safeAreaHeightAnchor` 直接给 `fretboardHostView` 施加全局高度约束。
- 改为以当前 split slot 为唯一高度上下文，把 `verticalHostHeightRatio` 解释为 `fretboard` 的目标/偏好高度语义：
- 当 viewport 足够时，`fretboard` 至少不应因下方 strip 被不必要压缩。
- 当 viewport 不足以同时容纳 strip 的内容高度、split spacing 和 `fretboard` 的目标高度时，才允许 `fretboard` 让步。
- 这样可以保留你指定的产品语义，同时消除“split 分高”和“safe area 定高”两套约束同时生效的问题。

### 5. 让 sceneContainerView 的总高度收口到 viewport

- 在 [NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift](NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift) 和 [NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift](NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift) 的 `configureLayout()` 中，给 `exerciseSceneRenderer.sceneContainerView` 增加与当前 viewport 对齐的高度约束，而不是只让它贴 `contentView` 的 top/bottom。
- 目标是让 exercise scene 自身成为“刚好一屏”的布局域；scroll view 仍保留，但不再让 scene 因内部 pane 约束无限变高。

### 6. 用 validation 锁住新高度语义和旧能力边界

- 在 [NoteMaster_Ver_1/Shared/Exercise/ExerciseCompositionValidation.swift](NoteMaster_Ver_1/Shared/Exercise/ExerciseCompositionValidation.swift) 中新增夹具，验证 `fretboardToNaturalNoteStrip` vertical split 的 child sizing 已从纯 `weight` 扩展为 “上 fill / 下 fitContent”。
- 补充 iOS/macOS manual checklist，覆盖：`positionPrompt` 下方 strip 不再被拉到超出首屏、按钮文字首屏可见、`verticalHostHeightRatio` 滑块仍存在且其目标高度语义未丢失、`naturalNoteStripAccessory` 若一并改造则行为一致。
- 若需要平台级 layout regression，可在现有 renderer validation 或 debug snapshot 基础上补一个 focused 验证，确认 scene 总高度不再由 `fretboardHostView` 的 safe-area 硬约束撑爆。

## 风险与关注点

- 这次改动的核心不是样式调参，而是 shared scene contract 和 renderer 高度分配模型的升级；回归重点应放在 vertical split 的高度链，而不是按钮样式本身。
- `verticalHostHeightRatio` 是现有迁移计划里要求保留的能力，因此不能简单删除；需要把它降到正确层级：由 split slot 消费，而不是由 leaf host 直接对全局 safe area 定高。
- `overlay`、`sideBySide`、`singleSurface`、纯 `piano` accessory 等路径都应继续走现有 `fill + weight` 行为，避免过度扩散。
