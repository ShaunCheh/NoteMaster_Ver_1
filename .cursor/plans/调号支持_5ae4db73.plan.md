# 调号支持分阶段计划

## 关键决策

- `pitch` 字符串继续表示“绝对书写音高”，不改当前 [NoteMaster_Ver_1/Shared/Staff/StaffScore.swift](NoteMaster_Ver_1/Shared/Staff/StaffScore.swift) 里 `StaffPitch -> NotePitch` 的语义。也就是说，`f#4` 仍然表示 F sharp；调号只负责决定“要不要显示 accidental glyph”，不反向改写音高本体。
- `keySignature` 的共享域模型建议使用 `fifths: Int`（`-7...7`）作为唯一真相源，而不是直接把 `G major`、`Bb` 之类字符串塞进领域层。这样布局、默认升降、验证器都可以围绕 circle-of-fifths 统一工作。
- `measures` 必须进入 [NoteMaster_Ver_1/Shared/Staff/StaffScore.swift](NoteMaster_Ver_1/Shared/Staff/StaffScore.swift) 成为主语义容器；`notes` 只作为 DTO/fixture 的兼容入口，在 decode 时自动包装成单小节，避免一开始就把现有 demo 全部打碎。
- 小节内临时记号状态由 `letter + octave` 维度追踪，并在每个 measure 起点重置为 key signature 默认值。这是方案 C 的核心，不应继续放在 [NoteMaster_Ver_1/Shared/Staff/StaffPitchLayout.swift](NoteMaster_Ver_1/Shared/Staff/StaffPitchLayout.swift) 里做单 note 决策。

## 当前架构里必须调整的点

- [NoteMaster_Ver_1/Shared/Staff/StaffScore.swift](NoteMaster_Ver_1/Shared/Staff/StaffScore.swift) 现在只有 `clef + notes`，还没有 `keySignature`、`measures`，所以调号上下文无处挂载。
- [NoteMaster_Ver_1/Shared/Staff/StaffPitchLayout.swift](NoteMaster_Ver_1/Shared/Staff/StaffPitchLayout.swift) 当前把 `accidentalSymbolID` 混在 `PositionedPitch` 里，说明“记不记 accidental”仍被当成几何问题处理；这与 key signature / measure reset 的真实语义不匹配。
- [NoteMaster_Ver_1/Shared/Staff/StaffSceneBuilder.swift](NoteMaster_Ver_1/Shared/Staff/StaffSceneBuilder.swift) 目前能在 clef 后排 note，但还没有“clef 后先排调号 cluster，再排 notes”的横向结构，也没有 accidental context。
- [NoteMaster_Ver_1/Shared/Staff/StaffValidation.swift](NoteMaster_Ver_1/Shared/Staff/StaffValidation.swift) 目前只覆盖 clef 与 notehead 主链路，不覆盖 key signature glyph 顺序、key-default accidental 抑制、跨小节 reset。

## 阶段 1：领域模型与 JSON 边界升级

涉及文件：

- [NoteMaster_Ver_1/Shared/Staff/StaffScore.swift](NoteMaster_Ver_1/Shared/Staff/StaffScore.swift)
- [NoteMaster_Ver_1/Shared/Staff/StaffScoreDecoding.swift](NoteMaster_Ver_1/Shared/Staff/StaffScoreDecoding.swift)
- [NoteMaster_Ver_1/Shared/Staff/StaffScoreFixtures.swift](NoteMaster_Ver_1/Shared/Staff/StaffScoreFixtures.swift)

动作：

- 新增 `StaffKeySignature`，内部只暴露 `fifths: Int` 和由此推导出的默认升降映射。
- 新增 `StaffMeasure`，由 `notes: [StaffScoreNote]` 组成。
- 将 `StaffScore` 升级为 `clef + keySignature + measures`；保留单小节兼容初始化入口，避免平台接线一次性大爆炸。
- 扩展 DTO：支持 `keySignature` / `调号`、`measures` / `小节`，并兼容现有 `notes` 入口；如果只传 `notes`，decode 时自动包装成一个 measure。
- 明确 decode 约束：canonical 入口优先支持 `{"fifths": 1}`；如需便捷字符串 token，可只放在 DTO 边界做别名解析，不把字符串传播进共享域模型。

验收：

- 共享层能表达“相同 clef、不同 key signature、多个 measures”的 `StaffScore`。
- 现有 demo fixture 可以平滑迁移，旧 `notes` JSON 在过渡阶段仍可继续解码。

## 阶段 2：拆出调号布局和临时记号上下文

涉及文件：

- 新增 [NoteMaster_Ver_1/Shared/Staff/StaffKeySignatureLayout.swift](NoteMaster_Ver_1/Shared/Staff/StaffKeySignatureLayout.swift)
- 新增 [NoteMaster_Ver_1/Shared/Staff/StaffAccidentalContext.swift](NoteMaster_Ver_1/Shared/Staff/StaffAccidentalContext.swift)
- 修改 [NoteMaster_Ver_1/Shared/Staff/StaffPitchLayout.swift](NoteMaster_Ver_1/Shared/Staff/StaffPitchLayout.swift)
- 复用 [NoteMaster_Ver_1/Shared/Staff/MusicGlyph.swift](NoteMaster_Ver_1/Shared/Staff/MusicGlyph.swift)

动作：

- 在 `StaffKeySignatureLayout` 中收口 treble/bass 下 `sharp` / `flat` 的标准顺序与垂直位置，输出一组 `glyph + centerY` 布局结果。
- 在 `StaffAccidentalContext` 中实现：从 `keySignature` 建立默认状态、按 note 更新小节内状态、判断某个 note 当前是否需要显示 accidental glyph。
- 将 [NoteMaster_Ver_1/Shared/Staff/StaffPitchLayout.swift](NoteMaster_Ver_1/Shared/Staff/StaffPitchLayout.swift) 缩回纯几何职责：只返回 `staffPosition / centerY / stemDirection / ledgerLineYs`，移除 `accidentalSymbolID`。
- 保持 [NoteMaster_Ver_1/Shared/Staff/MusicGlyph.swift](NoteMaster_Ver_1/Shared/Staff/MusicGlyph.swift) 继续复用现有 `.accidentalFlat/.accidentalNatural/.accidentalSharp`，不额外制造 renderer 复杂度。

验收：

- 给定 `clef + keySignature`，共享层能稳定给出调号 glyph 的顺序和垂直位置。
- 给定同一小节内的 note 序列，accidental context 能判断“需要显示 sharp/flat/natural”还是“应被 key signature / 前置临时记号抑制”。

## 阶段 3：重构 SceneBuilder 为“clef -> keySignature -> measures -> notes”

涉及文件：

- 修改 [NoteMaster_Ver_1/Shared/Staff/StaffSceneBuilder.swift](NoteMaster_Ver_1/Shared/Staff/StaffSceneBuilder.swift)
- 视情况少量调整 [NoteMaster_Ver_1/Shared/Staff/StaffSceneProvider.swift](NoteMaster_Ver_1/Shared/Staff/StaffSceneProvider.swift)
- 视情况少量调整 [NoteMaster_Ver_1/Shared/Staff/StaffScene.swift](NoteMaster_Ver_1/Shared/Staff/StaffScene.swift)

动作：

- 在 `StaffSceneBuilder` 中新增横向分区：`clefArea -> keySignatureArea -> noteArea`。
- 先生成 clef glyph，再生成 key signature glyph cluster，然后再对 measure 内 notes 做横向分布。
- note accidental 的 glyph 决策改由 `StaffAccidentalContext` 驱动，而不是直接读 `pitch.accidental`。
- context 在每个 measure 起点重置为 key signature 默认值；measure 内逐 note 更新。
- measure 语义先服务于 accidental reset，不强制同阶段加入 barline 绘制；barline 可作为后续独立增量，避免把范围从“调号支持”扩成“完整排版系统”。
- 当前 [NoteMaster_Ver_1/Shared/Staff/StaffSceneBuilder.swift](NoteMaster_Ver_1/Shared/Staff/StaffSceneBuilder.swift) 里的 `accidentalFrame(...)`、note area inset、以及 key signature 后的间距都应改为围绕“key signature cluster 宽度”计算，不再只围绕单 note accidental 预留空间。

验收：

- `clef + keySignature + measures` 能生成完整 scene，且 note 不会侵入 key signature 区域。
- 同一个 `f#4` 在 C 大调与 G 大调下，absolute pitch 不变，但 accidental glyph 显示策略会正确不同。
- 同一个小节内第二个同音级 accidental 会被正确抑制；跨小节后会恢复为 key signature 默认规则。

## 阶段 5：补验证器与调号 fixture 矩阵

涉及文件：

- 修改 [NoteMaster_Ver_1/Shared/Staff/StaffValidation.swift](NoteMaster_Ver_1/Shared/Staff/StaffValidation.swift)
- 修改 [NoteMaster_Ver_1/Shared/Staff/StaffScoreFixtures.swift](NoteMaster_Ver_1/Shared/Staff/StaffScoreFixtures.swift)

动作：

- 新增 key signature fixture：至少覆盖 `C / G / D / F / Bb`，兼顾 `treble` 与 `bass`。
- 验证 key signature glyph 数量、sharp/flat 顺序、clef 下的垂直位置、以及 noteArea 起点不会压到 key signatureArea。
- 验证同小节 accidental 抑制与跨小节 reset，例如：`G major` 下 `f#4, f#4 | f#4, f4`；以及 `Bb major` 下 `bb3, b3`。
- 手工清单新增：切 clef、切不同 key signature fixture、观察同小节/跨小节 accidental 显示是否符合预期。
- 视需要补一组“noteheadsOnly / fullNotation”显示策略回归，避免调号支持把之前排障期修复的 notehead 可见性重新打坏。

验收：

- key signature 与 accidental context 具备可重复跑的共享层验证，不依赖 UI 快照。
- 后续继续加 barline、和弦、拍号时，可以直接复用 `measures + keySignature + accidentalContext` 这条共享层骨架。

## 实施顺序建议

1. 先完成领域模型与 decode，再拆 accidental context；不要让 `SceneBuilder` 一边继续猜 JSON，一边处理调号语义。
2. 然后重构 `StaffSceneBuilder` 的横向分区和 accidental 决策。
3. 最后再恢复完整显示策略并补验证器，确保不是一边扩能力一边失去护栏。

## 范围控制

- 第一版只做调号和小节语义，不强绑 barline 绘制和拍号系统。
- 第一版不把 key signature 接进 settings UI；继续由共享 fixture 提供 demo，避免把任务扩成整套控制面板改造。
- 如果后续需要做“显式 courtesy accidental”或“minor/major 名义调式标签”，再在 DTO 边界增量扩展，不提前污染当前共享域模型。
