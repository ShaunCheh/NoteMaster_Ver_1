# 位置题音名公平修改计划

## 目标

把 position prompt 的出题策略改成三层公平：

- 弦公平：继续保持当前每轮每弦一次。
- 音名公平：在已选中的某根弦上，当前候选音名按最低命中优先分配，长期概率均匀。
- 格子公平：在已选中的 `(弦, 音名)` 组内，再按最低命中优先选择具体格子，并尽量避开上一题同格。

本计划默认的业务语义是：

- 只在“当前弦上、当前 filter 后实际存在的音名”之间做均匀分配。
- 不强行让当前弦上不存在的选中音名参与轮次。
- 答错仍不换题，答对才推进到下一题。

## 现状基线

当前共享调度器位于 [Shared/Fretboard/FretboardNaturalNoteTrainer.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardNaturalNoteTrainer.swift)。

- `PositionPromptSession.SchedulingState` 目前只维护 `remainingStringsInRound` 和 `cellHitCounts`。
- `selectPositionPromptCell()` 当前是“先选弦，再在该弦上按最低 `cellHitCounts` 选格”。
- 控制器层只消费 session / evaluation，不感知调度细节，入口在 [Platform/iOS/iOSViewController.swift](NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift) 和 [Platform/macOS/macOSViewController.swift](NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift)。
- 自动验证主要集中在 [Shared/Fretboard/FretboardValidation.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardValidation.swift)，当前断言已经把“每轮每弦一次 + 弦内最低格子命中优先”写死为测试语义。

## 核心改造

### 1. 扩展共享调度状态

修改 [Shared/Fretboard/FretboardNaturalNoteTrainer.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardNaturalNoteTrainer.swift) 中的 `PositionPromptSession.SchedulingState`：

- 保留 `remainingStringsInRound`，继续承载弦轮巡。
- 保留 `cellHitCounts`，但把它明确降级为第三层“格子公平”。
- 新增 note 级统计，例如 `noteHitCountsByString: [Int: [PitchClass: Int]]` 或等价结构，用于承载第二层“弦内音名公平”。
- 让新增状态与 `candidatePoolSignature` 同生命周期；candidate pool 改变时必须一起重置。

原因：当前状态里只有格子命中次数，无法表达“同一根弦上先选音名，再选格子”的公平目标。把 note 级状态并入 `SchedulingState`，可以复用现有 `carryingOver`、`seededPositionPromptSchedulingState()` 和 candidate pool reset 模型，而不需要改平台接口。

### 2. 重写选题算法，但保留外层 API

仍然以 [Shared/Fretboard/FretboardNaturalNoteTrainer.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardNaturalNoteTrainer.swift) 为唯一真相源，保持 `makePositionPromptSession()` / `handlePositionPromptAnswer()` 的对外签名不变，内部只重写私有调度路径：

- 在 `selectPositionPromptCell()` 中继续先确定 `activeRoundStrings` 并随机选一根弦。
- 针对选中的弦，把 `stringCandidates` 先按 `PitchClass` 分组。
- 在这些音名组之间，优先选择 note hit 最低的音名；若并列，再随机选择一个音名。
- 在选中的 `(弦, 音名)` 组内，再沿用当前的最低 `cellHitCounts` 优先，并尽量排除 `excludedCell`。
- 选定 prompt 后，同时更新：
  - `remainingStringsInRound`
  - `noteHitCountsByString`
  - `cellHitCounts`

建议把当前私有 helper 拆成更清晰的层级：

- `positionPromptCandidateCellsByString()` 保留。
- 新增按弦内音名分组的 helper，例如 `positionPromptCandidateCellsByStringAndPitchClass()`。
- 把 `selectPositionPromptCell()` 内部逻辑拆成“选弦 / 选音 / 选格”三个局部 helper，避免验证层无法对齐实现语义。

## 兼容性与不变量

### 3. 收敛运行时断言和 debug 语义

同步更新 [Shared/Fretboard/FretboardNaturalNoteTrainer.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardNaturalNoteTrainer.swift) 中的 precondition / validation / debug：

- `SchedulingState.init`：为新增 note 级统计建立与 `cellHitCounts` 一致的正数约束或“仅记录已命中的键”约束。
- `SchedulingState.initial(...)`：首题初始化时要同时种下 cell hit 和 note hit，保证首题与后续题的计数语义一致。
- `validatePositionPromptSession(...)`：新增 note 级状态合法性检查，确保当前 prompt 的 `(弦, 音名)` 已被正确记账。
- `positionPromptSchedulingDebugText(...)` 与 `selectPrompt` 日志：增加弦内音名计数摘要，避免日志仍只反映 cell 级公平，排查时失真。

## 验证与回归

### 4. 重写 position prompt 验证语义

修改 [Shared/Fretboard/FretboardValidation.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardValidation.swift)：

- 保留“答错不换题”“candidate pool/filter 仍然正确”的断言。
- 重写 `validateCorrectAdvance(...)` 一类断言，从“当前弦内最低格子命中优先”改成：
  - 下一题的弦必须仍然遵循当前轮剩余弦集合。
  - 在该弦上，下一题音名必须遵循最低 note hit 优先。
  - 在该 `(弦, 音名)` 组内，下一题格子必须遵循最低 cell hit 优先及排除当前格。
- 重写 `roundRobinSequence` 验证，继续保证“每轮每弦一次”，同时新增“每根弦上长期音名命中趋于均衡”的序列级检查。
- 增加 filter 场景：
  - 默认音名集合。
  - 增减音名后的候选池。
  - 极端配置：某根弦上只有 1 个可用音名。
  - 某根弦上某音名有多个格位时，验证 note 公平和 cell 公平不会互相覆盖。

## 平台层影响

### 5. 保持控制器入口不变，只校正日志预期

[Platform/iOS/iOSViewController.swift](NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift) 和 [Platform/macOS/macOSViewController.swift](NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift) 预计不需要改签名：

- `ensurePositionPromptSession()`、`handlePositionPromptAnswer()`、`applyPositionPromptProjection()` 继续只处理 session 生命周期和 UI feedback。
- 如需增强排障能力，只更新 trainer 层日志文本即可；控制器日志可继续打印 `promptPitchClass + string + fret`。

## 实施顺序

1. 先在 [Shared/Fretboard/FretboardNaturalNoteTrainer.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardNaturalNoteTrainer.swift) 引入 note 级调度状态与 helper，保持编译通过。
2. 重写 `selectPositionPromptCell()` 的内部流程，落地“弦 -> 音 -> 格”三层选择。
3. 对齐 `SchedulingState.initial`、`seededPositionPromptSchedulingState()`、`validatePositionPromptSession()` 和 debug 输出。
4. 在 [Shared/Fretboard/FretboardValidation.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardValidation.swift) 重写断言并增加新的公平性回归场景。
5. 最后检查 iOS/macOS 控制器是否只需更新日志断言或无需改动。

## 风险点

- 当前 `SchedulingState` 是纯值类型并参与 `Equatable`，新增 note 级状态后，任何 session 对比逻辑都要保持 deterministic。
- 需要避免把“音名公平”误做成“全局音名公平”；目标应是“当前弦内、当前候选池内的音名公平”。
- 需明确第一题的记账时机，否则首题可能比后续题少一次 note hit，造成长期轻微偏差。
- 如果某根弦上某个音名只有一个格，而另一音名有多个格，验证要确保 note 公平优先级高于 cell 公平。

## 预期结果

修改完成后，position prompt 应满足：

- 轮次层面仍是每轮每弦一次。
- 在任意一根弦上，当前选中音名的长期出题概率近似均匀。
- 当某个音名在同一根弦上有多个位置时，这些位置再在该音名内部做长期均匀分配。
