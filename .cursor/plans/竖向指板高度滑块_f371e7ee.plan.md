# 竖向指板高度滑块方案

## 目标

- 仅在 `vertical` 模式显示高度滑块。
- 滑块位置放在 `staffView` 上方，也就是 `staffControlPanelView` 下方；不要放在 `staffView` 与 `fretboardHostView` 之间。
- 滑块值只控制外层 `fretboardHostView` 的高度比例，不进入指板几何配置，避免把页面布局状态混进 [NoteMaster_Ver_1/Shared/Fretboard/FretboardConfiguration.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardConfiguration.swift)。

## 关键现状

- 当前 vertical 高度出口在 [NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift](NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift) 和 [NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift](NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift) 的 `verticalFretboardHostHeightConstraint`，默认比例来自 `Layout.verticalFretboardHostHeightRatio`。
- 当前页面顺序是 `buttonPanelView -> staffControlPanelView -> staffView -> fretboardHostView`；本次应调整为 `buttonPanelView -> staffControlPanelView -> fretboardControlPanelView -> staffView -> fretboardHostView`。
- 连续值控制最成熟的复用模式已在 [NoteMaster_Ver_1/Shared/Controls/StaffControlPanelModel.swift](NoteMaster_Ver_1/Shared/Controls/StaffControlPanelModel.swift)、[NoteMaster_Ver_1/Shared/Controls/StaffControlPanelSnapshotBuilder.swift](NoteMaster_Ver_1/Shared/Controls/StaffControlPanelSnapshotBuilder.swift)、[NoteMaster_Ver_1/Platform/iOS/Controls/iOSStaffControlPanelView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSStaffControlPanelView.swift) 和对应 macOS 视图里落地。

## 修改方案

- 在 [NoteMaster_Ver_1/Shared/Controls/FretboardDisplayState.swift](NoteMaster_Ver_1/Shared/Controls/FretboardDisplayState.swift) 新增 `verticalHostHeightRatio`（或等价命名），默认值沿用当前 `0.72`，并提供共享状态级别的写入口；范围在共享层 clamp，例如 `0.35...0.9`。
- 新增共享控制面板模型与快照构建：
  - [NoteMaster_Ver_1/Shared/Controls/FretboardControlPanelModel.swift](NoteMaster_Ver_1/Shared/Controls/FretboardControlPanelModel.swift)
  - [NoteMaster_Ver_1/Shared/Controls/FretboardControlPanelSnapshotBuilder.swift](NoteMaster_Ver_1/Shared/Controls/FretboardControlPanelSnapshotBuilder.swift)
  这里定义 `FretboardControlEvent.setVerticalHostHeightRatio(CGFloat)`、slider item、显示文本与共享层 clamp 逻辑。
- 新增平台薄视图，复用 Staff slider 模式：
  - [NoteMaster_Ver_1/Platform/iOS/Controls/iOSFretboardControlPanelView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSFretboardControlPanelView.swift)
  - [NoteMaster_Ver_1/Platform/macOS/Controls/macOSFretboardControlPanelView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSFretboardControlPanelView.swift)
  保持 `slider -> makeEvent(value:) -> onEvent` 的数据流，平台层不做业务解释。
- 在 [NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift](NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift) 和 [NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift](NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift) 中：
  - 增加 `fretboardControlPanelView` 与 `handleFretboardControlEvent(_:)`。
  - 把新面板插入 `staffView` 上方。
  - 在 `applyFretboardDisplayState()` 中同步 panel model、显示/隐藏状态，并根据 `displayState.verticalHostHeightRatio` 重建 `verticalFretboardHostHeightConstraint`。
- 保持 [NoteMaster_Ver_1/Platform/iOS/iOSFretboardView.swift](NoteMaster_Ver_1/Platform/iOS/iOSFretboardView.swift) 与 [NoteMaster_Ver_1/Platform/macOS/macOSFretboardView.swift](NoteMaster_Ver_1/Platform/macOS/macOSFretboardView.swift) 的 intrinsic 逻辑不变，让它们继续根据 host 高度自动反推 width。

## 实施注意点

- `NSLayoutConstraint` 的 `multiplier` 不能原地修改；ratio 变化时必须停用旧的 `verticalFretboardHostHeightConstraint`，按新值重建并重新激活。
- `horizontal` 模式下隐藏 `fretboardControlPanelView`，避免出现无效滑块；切回 `vertical` 时恢复上次共享状态中的比例。
- 不把该比例塞进 `ButtonPanelModel`；`ButtonPanel` 继续只承载离散按钮动作，连续值走独立 `FretboardControlPanel`。

## 验收标准

- `vertical` 模式下可通过滑块连续调整指板高度，占比变化立即体现在 `fretboardHostView` 上。
- 面板位置固定在五线谱上方，不出现在五线谱和指板之间。
- 指板仍保持水平居中、宽度自适应、命中不漂移；切换乐器与切换 `horizontal/vertical` 后状态同步刷新。
- 双平台无约束冲突，`swiftc -typecheck` 通过，并补充手工回归清单。
