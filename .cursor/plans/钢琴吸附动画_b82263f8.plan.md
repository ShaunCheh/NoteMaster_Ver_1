# 钢琴吸附显式动画计划

## 目标

- 保持拖动结束时先停留在连续位置，再由 shared `CALayer` 执行 `0.10` 到 `0.12` 秒的显式短动画吸附到最近锚点。
- 复用现有 `rows -> scene -> rowLayer.scene` 渲染链，不把时间轴塞进 reducer，不重写 `[NoteMaster_Ver_1/Shared/Piano/PianoSceneBuilder.swift](NoteMaster_Ver_1/Shared/Piano/PianoSceneBuilder.swift)` / `[NoteMaster_Ver_1/Shared/Piano/PianoRowLayer.swift](NoteMaster_Ver_1/Shared/Piano/PianoRowLayer.swift)` 的逐键绘制逻辑。

## 关键落点

- `[NoteMaster_Ver_1/Shared/Piano/PianoInteractionReducer.swift](NoteMaster_Ver_1/Shared/Piano/PianoInteractionReducer.swift)`：`finalizeScaleDrag(...)`
- `[NoteMaster_Ver_1/Shared/Piano/PianoKeyboardLayer.swift](NoteMaster_Ver_1/Shared/Piano/PianoKeyboardLayer.swift)`：`synchronizeSublayerState()`
- `[NoteMaster_Ver_1/Platform/iOS/Controls/iOSPianoKeyboardView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSPianoKeyboardView.swift)` / `[NoteMaster_Ver_1/Platform/macOS/Controls/macOSPianoKeyboardView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSPianoKeyboardView.swift)`：`applyReduction(_:)`

```swift
// 当前立即吸附的关键路径。
if configuration.snapEnabled {
    resolvedRows = normalizeRowsAfterScaleDrag(
        finalRows,
        interaction: interaction,
        configuration: configuration
    )
} else {
    resolvedRows = finalRows
}

nextState.rows = resolvedRows
nextState.activeInteraction = nil
```

## 实施步骤

1. 扩展 shared 输出契约。

- 给 `PianoReduction` 增加可选 `presentationCommand`。
- 新增 `PianoPresentationCommand.animateScaleSnap(PianoScaleSnapAnimationPlan)`。
- `PianoScaleSnapAnimationPlan` 至少包含 `fromRows`、`toRows`、`affectedRowIndices`、`duration`。
- 调整两个 platform view 的 `applyReduction(_:)` guard，使 `presentationCommand` 单独存在时也会被消费。

1. 改造 `finalizeScaleDrag(...)`。

- `snapEnabled == false` 保持现状。
- `snapEnabled == true` 时：
- `nextState.rows = finalRows`
- `nextState.activeInteraction = nil`
- 计算 `snappedRows`
- 输出 `.animateScaleSnap(plan)`
- 不在 reducer 内立即提交 `snappedRows`

1. 新增 shared 插值 helper。

- 新建 `[NoteMaster_Ver_1/Shared/Piano/PianoPresentation.swift](NoteMaster_Ver_1/Shared/Piano/PianoPresentation.swift)`，或放到 `[NoteMaster_Ver_1/Shared/Piano/PianoGeometry.swift](NoteMaster_Ver_1/Shared/Piano/PianoGeometry.swift)`。
- 不插值 `startNote`。
- 用 `noteLeadingX(startNote)` 计算 `fromAnchorX` / `toAnchorX`。
- 插值 `currentAnchorX`。
- 生成仅用于渲染的 synthetic `PianoRowState`。
- 继续复用 `PianoSceneBuilder`、`visibleKeys`、`scaleMarkers`。

1. 在 shared `PianoKeyboardLayer` 增加显式吸附动画上下文。

- 新增 `presentationRowsOverride`。
- 新增 `activeScaleSnapAnimation`。
- 新增 `startScaleSnapAnimation(plan:completion:)`。
- 新增 `cancelScaleSnapAnimation(materializeCurrentFrame:)`。
- `synchronizeSublayerState()` 优先使用 `presentationRowsOverride ?? state.rows`。
- 第一版时长固定 `0.10` 到 `0.12` 秒，使用 `easeOutCubic`。

1. 在 iOS / macOS wrapper 接入动画命令。

- `[NoteMaster_Ver_1/Platform/iOS/Controls/iOSPianoKeyboardView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSPianoKeyboardView.swift)`。
- `[NoteMaster_Ver_1/Platform/macOS/Controls/macOSPianoKeyboardView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSPianoKeyboardView.swift)`。
- `applyReduction(_:)` 改成先应用 `reduction.nextState`。
- 再消费 `.animateScaleSnap(plan)`。
- 动画期间画面使用 `presentationRowsOverride`。
- 动画完成后再把 `componentState.rows` 提交成 `plan.toRows`。
- 再补发最终 `onRowsChanged(plan.toRows)`。

1. 处理动画中断和外部覆盖。

- 新一轮 `began` 到来前，如果当前有 snap 动画，先把当前 presentation frame 物化成 `componentState.rows`。
- 然后取消动画，并从这个位置开始新的 hit test / reducer。
- 外部 `rows` 替换、`configuration` 变化、行数变化时也统一取消动画，避免视觉位置和逻辑位置分叉。

1. 补 validation 和回归清单。

- `[NoteMaster_Ver_1/Shared/Piano/PianoValidation.swift](NoteMaster_Ver_1/Shared/Piano/PianoValidation.swift)`。
- 校验 `snapEnabled == true` 时 reducer 返回的是 `finalRows + presentationCommand`，不是立即 snapped。
- 校验 `snapEnabled == false` 时没有动画命令。
- 校验插值 helper 在 `progress = 0 / 0.5 / 1` 时结果正确。
- 校验离开 `B` 区结束拖动时，也能走同一套吸附动画收口。
- 校验多行 `cascade` 下所有受影响行同步动画。
- 手工回归重点测 iOS / macOS 两端的：正常抬手、拖出 `B` 区、动画中再次开始拖动、`rowOnly` / `cascade`、黑键起始音。

## 实现边界

- 不把时间推进逻辑塞进 `PianoInteractionReducer`，避免 reducer 从纯状态转换变成带时序的控制器。
- 不在 `PianoRowLayer` 里逐个 key rect 手工插值，继续复用 `rows -> scene -> rowLayer.scene` 这条链。
- 不采用“logic state 先 snap，再只做视觉动画”的路径，避免动画窗口内 hit test 位置、画面位置、外部 host 持有的 rows 短暂不一致。
- controller 层原则上不改；主要改动集中在 `Shared/Piano` 和两个 platform view wrapper。
