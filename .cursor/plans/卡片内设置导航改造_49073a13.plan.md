# 卡片内 Settings Navigation 分阶段计划

## 目标

- 保留现有 settings 外观：遮罩、居中 card、右上关闭，不做全屏 stack，不接系统 `Navigation`。
- `iOS` / `macOS` 共用一套 settings 页面树；卡片内部支持 `root -> section -> deeper detail`。
- 继续保留现有业务单一真相：`[NoteMaster_Ver_1/Shared/Controls/SettingsPanelStateContext.swift](NoteMaster_Ver_1/Shared/Controls/SettingsPanelStateContext.swift)`、`[NoteMaster_Ver_1/Shared/Controls/SettingsPanelModel.swift](NoteMaster_Ver_1/Shared/Controls/SettingsPanelModel.swift)` 里的 `SettingsPanelEvent`，以及 `[NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift](NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift)` / `[NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift](NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift)` 中的 `handleSettingsPanelEvent(_:)`。

## 固定架构决策

- 保留共享输入与事件层：`[NoteMaster_Ver_1/Shared/Controls/SettingsPanelStateContext.swift](NoteMaster_Ver_1/Shared/Controls/SettingsPanelStateContext.swift)`、`[NoteMaster_Ver_1/Shared/Controls/SettingsPanelSnapshotBuilder.swift](NoteMaster_Ver_1/Shared/Controls/SettingsPanelSnapshotBuilder.swift)`、`[NoteMaster_Ver_1/Shared/Controls/SettingsPanelModel.swift](NoteMaster_Ver_1/Shared/Controls/SettingsPanelModel.swift)`。
- 新增共享“页面树”层：`SettingsNavigationModel` + `SettingsNavigationSnapshotBuilder`，路径放在 `[NoteMaster_Ver_1/Shared/Controls/](NoteMaster_Ver_1/Shared/Controls/)`；依赖方向固定为 `SettingsPanelStateContext -> SettingsPanelSnapshotBuilder -> SettingsNavigationSnapshotBuilder -> NavigationModel`。
- 保留现有 container 外壳：`[NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsContainerView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsContainerView.swift)`、`[NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsContainerView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsContainerView.swift)` 继续负责 backdrop、card、关闭、最大高度、主滚动区域。
- 统一单卡片头部：直接扩展现有 `headerView`，让它承载 `backButton + titleLabel + closeButton`。`close` 仍是容器级行为；`back/title` 由 navigator 提供状态、由 container header 渲染。这样避免出现两个固定 bar。
- 主纵向 `scrollView` 继续留在 container，不下放到 page view；路由切换只发生在 scroll 内容区内部。
- `routeStack` 不进入 `SettingsPanelStateContext`，而是留在平台 `NavigatorView` 中作为本地 UI 状态。
- 现有 `[NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsPanelView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsPanelView.swift)` 和 `[NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsPanelView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsPanelView.swift)` 暂不重命名，先明确把它们降级为“表单页渲染器”；等行为稳定后再决定是否做命名清理。

## Phase 1：共享导航模型落地

目标：把“设置页树”先建出来，但不立即改 UI。

涉及文件：

- 新增 `[NoteMaster_Ver_1/Shared/Controls/SettingsNavigationModel.swift](NoteMaster_Ver_1/Shared/Controls/SettingsNavigationModel.swift)`
- 新增 `[NoteMaster_Ver_1/Shared/Controls/SettingsNavigationSnapshotBuilder.swift](NoteMaster_Ver_1/Shared/Controls/SettingsNavigationSnapshotBuilder.swift)`
- 复用 `[NoteMaster_Ver_1/Shared/Controls/SettingsPanelSnapshotBuilder.swift](NoteMaster_Ver_1/Shared/Controls/SettingsPanelSnapshotBuilder.swift)`
- 复用 `[NoteMaster_Ver_1/Shared/Controls/SettingsPanelModel.swift](NoteMaster_Ver_1/Shared/Controls/SettingsPanelModel.swift)`

实施内容：

- 新建 `SettingsRouteID`、`SettingsRouteItem`、`SettingsPageModel`、`SettingsPageContent`、`SettingsNavigationModel`。
- 第一版 builder 不做复杂拆页，先把当前 `panelModel.sections` 投影为：
  - `root`：section 入口列表
  - `section(SettingsSectionID)`：单 section 表单页
- `SettingsRouteID` 从第一天起就预留深层路由位，例如 `trainerPositionFilter`、`pianoAdvanced`，避免后续再次重构路由类型。
- root 页顺序必须与 `panelModel.sections` 一致，不能让平台层自己重新排序。

阶段验收：

- 对同一个 `SettingsPanelStateContext`，`SettingsNavigationSnapshotBuilder.makeModel` 生成的 root route items 与 `SettingsPanelSnapshotBuilder.makeModel(...).sections` 一一对应、顺序一致。
- 动态 section 显隐仍完全受共享层控制，例如 `Layout`、`Trainer` 子内容的显隐规则不下沉到平台层。

## Phase 2：共享验证与回归挂钩

目标：让新页面树和现有 settings 投影一样可验证，避免 iOS/macOS 后续漂移。

涉及文件：

- 新增 `[NoteMaster_Ver_1/Shared/Controls/SettingsNavigationValidation.swift](NoteMaster_Ver_1/Shared/Controls/SettingsNavigationValidation.swift)`
- 更新 `[NoteMaster_Ver_1/Platform/iOS/iOSAppDelegate.swift](NoteMaster_Ver_1/Platform/iOS/iOSAppDelegate.swift)`
- 更新 `[NoteMaster_Ver_1/Platform/macOS/macOSAppDelegate.swift](NoteMaster_Ver_1/Platform/macOS/macOSAppDelegate.swift)`
- 参考现有模式：`[NoteMaster_Ver_1/Shared/Fretboard/FretboardValidation.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardValidation.swift)`

实施内容：

- 新建 `SettingsNavigationValidationRunner.runAndReportIfNeeded(platform:)`，沿用现有 `runAndReportIfNeeded` 风格，不把导航校验继续塞进已经很大的 `FretboardValidation.swift`。
- 首批校验覆盖：
  - root 页 section 顺序
  - 某些上下文下哪些 route 存在/不存在
  - route 失效后的回退规范（回到最近仍有效的父级，最后兜底 root）
  - 深层 route 的标题与承载 section 是否正确
- 在 iOS/macOS AppDelegate 启动校验链里并列挂接，保持两端启动即能发现共享投影回归。

阶段验收：

- iOS/macOS 启动时都能跑 navigation projection 校验。
- root/section 投影错误能在启动日志里被直接报出，而不是等到 UI 手测才发现。

## Phase 3：双平台 container 壳层改造

目标：不改 card 外观，只把卡片内部从“单页长表单”改成“统一 header + navigator 内容区”。

涉及文件：

- `[NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsContainerView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsContainerView.swift)`
- `[NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsContainerView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsContainerView.swift)`

实施内容：

- 保留 backdrop、card、阴影、圆角、`maximumScrollHeight`、`onDismissRequest`、背景点击关闭。
- 扩展现有 `headerView`：新增 `backButton` 与 `titleLabel`，保留 `closeButton`。
- 将当前“`scrollView + contentView + settingsPanelView`”中的直接 `settingsPanelView` 挂载，替换为 `navigatorHostView` 或 `navigatorContentView`。
- `headerView` 固定在 card 顶部，不随内容滚动；scroll 仍位于 header 下方。
- container 对外 API 从单一 `model` 逐步切换为 `navigationModel`；`onEvent` 和 `onDismissRequest` 保持不变。

阶段验收：

- 在只有 `root` 或只有单一 page 的情况下，card 的尺寸、关闭行为、遮罩行为与现在保持一致。
- 头部只有一行，不会出现“container header + navigator bar”双层固定条。

## Phase 4：iOS / macOS Navigator 空壳与 root->section 导航

目标：让两个平台都先跑通“卡片内 root -> section”的最小可用导航。

涉及文件：

- 新增 `[NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsNavigatorView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsNavigatorView.swift)`
- 新增 `[NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsNavigatorView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsNavigatorView.swift)`
- 新增 `[NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsIndexPageView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsIndexPageView.swift)`
- 新增 `[NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsIndexPageView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsIndexPageView.swift)`
- 复用 `[NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsPanelView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsPanelView.swift)`
- 复用 `[NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsPanelView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsPanelView.swift)`
- 更新 `[NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift](NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift)`
- 更新 `[NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift](NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift)`

实施内容：

- `NavigatorView` 只负责：维护 `routeStack`、渲染当前 route 页面、发布 `canPop/currentTitle` 给 container header、执行卡片内转场。
- iOS 用 `UIView.animate` 做“右进左出 / 左进右出”；macOS 用 `NSAnimationContext` 做同语义转场。
- root page 用新的 `IndexPageView` 渲染 route item 列表；点击后 push 到对应 section。
- section detail page 继续复用现有 `*SettingsPanelView`，但只喂一个精简后的 `SettingsPanelModel(sections: [section])`。
- `iOSViewController.applySettingsPanelState()` / `macOSViewController.applySettingsPanelState()` 从 `SettingsPanelSnapshotBuilder.makeModel(...)` 切换为 `SettingsNavigationSnapshotBuilder.makeModel(...)`；`handleSettingsPanelEvent(_:)` 逻辑保持不动。

阶段验收：

- `root -> Page / Trainer / Fretboard / Staff / Layout / Piano / Debug` 能在卡片内导航。
- 点击设置项后，业务状态仍通过现有 `SettingsPanelEvent -> handleSettingsPanelEvent(_:)` 更新，并刷新当前页内容。
- route 改变时，header 的 `back/title/close` 行为正确；close 永远关闭整个 card，back 只退卡片内一层。

## Phase 5：深层页拆分重区

目标：在最小导航稳定后，再拆真正臃肿的 section，避免一开始就过度设计。

优先候选：

- `Trainer`：先拆 `Exercise` 与 `Position Filter`
- `Piano`：视行数拆 `Behavior` / `Appearance`
- `Staff`：视复杂度拆 `Clef` / `Layout`

涉及文件：

- `[NoteMaster_Ver_1/Shared/Controls/SettingsNavigationSnapshotBuilder.swift](NoteMaster_Ver_1/Shared/Controls/SettingsNavigationSnapshotBuilder.swift)`
- `[NoteMaster_Ver_1/Shared/Controls/SettingsNavigationModel.swift](NoteMaster_Ver_1/Shared/Controls/SettingsNavigationModel.swift)`
- root/index page 与 form page 相关平台文件

实施内容：

- 不再让所有重区都停留在单 section 页面；改为共享 builder 决定哪些 route 进入二级甚至三级页面。
- 深层页是否存在，仍由共享状态决定。例如仅在 `positionPrompt` 模式下暴露 `Trainer Filter` route。
- 保证 root 页仍简洁，只放主要分类，不把所有叶子设置项平铺回 root。

阶段验收：

- 至少 `Trainer` 能从 section 级别进一步拆成更清晰的子页。
- 深层 route 的出现/消失与当前 settings 状态保持一致，不在某个平台单独 hardcode 条件。

## Phase 6：清理、可访问性与回归收口

目标：把阶段性实现收敛成可长期维护的结构。

涉及文件：

- 双平台 container / navigator / index page / panel view
- 双平台 view controller
- 新旧 validation runner

实施内容：

- 对齐 `accessibilityIdentifier` / `accessibilityLabel`：新增 `settings-navigation-back-button`、`settings-navigation-title`、route item 标识，保持与现有 `settings-container-*` 风格一致。
- 做 route reconciliation：当状态变化导致当前 route 不再有效时，自动退到最近仍有效的父页，最后兜底 `root`。
- 补充手工回归清单：关闭、返回、深层页切换、动态 route 消失、切换 exercise mode 后当前页是否正确刷新、两端动画/布局是否对齐。
- 确认 `*SettingsPanelView` 在新架构里已稳定只承担“表单页渲染器”职责，再决定是否做后续命名清理；该清理不与主功能耦合。

阶段验收：

- iOS/macOS 卡片内导航结构对齐，交互一致，业务事件链不分叉。
- 现有 settings 相关状态同步、startup validation、无障碍标识都能在新结构下继续工作。

## 实施顺序建议

- 先做 Phase 1 + Phase 2，先把共享页面树和校验建起来。
- 再做 Phase 3 + Phase 4，让 root->section 在双平台同时落地。
- 最后做 Phase 5 + Phase 6，逐步拆深重区并清理收口。
