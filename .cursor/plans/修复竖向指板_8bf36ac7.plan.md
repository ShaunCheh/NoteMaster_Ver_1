# 修复 macOS 竖向指板坐标

## 根因结论

- [NoteMaster_Ver_1/Shared/Fretboard/VerticalFretboardGeometryStrategy.swift](NoteMaster_Ver_1/Shared/Fretboard/VerticalFretboardGeometryStrategy.swift) 和 [NoteMaster_Ver_1/Shared/Fretboard/FretboardValidation.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardValidation.swift) 已经把 `vertical` 契约固定为“上空弦下高品、品位沿 y 递增”。shared scene 本身不是根因。
- [NoteMaster_Ver_1/Platform/macOS/macOSFretboardView.swift](NoteMaster_Ver_1/Platform/macOS/macOSFretboardView.swift) 当前直接把 raw `NSView` 本地坐标送进 `FretboardGeometry.hitTest(...)`，而 [NoteMaster_Ver_1/Shared/Fretboard/FretboardBoardLayer.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardBoardLayer.swift) 的日志已经证明 macOS draw context 仍是 bottom-left；这和 shared scene 的 top-left 语义不一致。
- 现有 staff 链路已经有对照实现：[NoteMaster_Ver_1/Platform/macOS/macOSStaffView.swift](NoteMaster_Ver_1/Platform/macOS/macOSStaffView.swift) 通过 `contextNormalizationMode = .flipYToTopLeft` 明确收口平台坐标归一化。fretboard 应复用同一设计思路，而不是反向改 scene 公式。

## 实施计划

### 1. 在 fretboard 渲染根层补坐标归一化契约

- 参考 staff 的 root-layer 模式，在 [NoteMaster_Ver_1/Shared/Fretboard/FretboardLayer.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardLayer.swift) 增加 `contextNormalizationMode`，并把它下发给 [NoteMaster_Ver_1/Shared/Fretboard/FretboardBoardLayer.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardBoardLayer.swift) 与 [NoteMaster_Ver_1/Shared/Fretboard/FretboardLabelsLayer.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardLabelsLayer.swift)。
- 在 `board/labels` 的 `draw(in:)` 入口统一应用 `translateBy(x: 0, y: bounds.height)` + `scaleBy(x: 1, y: -1)`，让 macOS vertical 与 shared scene 的 top-left 语义一致。
- 启用范围只限定在 macOS `displayMode == .vertical`，避免误伤当前未报错的 horizontal 视觉结果。

### 2. 让 macOS hitTest 走与绘制完全一致的坐标变换

- 在 [NoteMaster_Ver_1/Platform/macOS/macOSFretboardView.swift](NoteMaster_Ver_1/Platform/macOS/macOSFretboardView.swift) 收口一个单一 helper，把 `convert(event.locationInWindow, from: nil)` 得到的 bottom-left 本地坐标，按与绘制同样的规则转换到 shared scene 语义后，再送入 `FretboardGeometry.hitTest(...)`。
- 这一层不要改 [NoteMaster_Ver_1/Shared/Fretboard/VerticalFretboardGeometryStrategy.swift](NoteMaster_Ver_1/Shared/Fretboard/VerticalFretboardGeometryStrategy.swift) 的公式；scene 与 hitTest 继续共用同一份 shared 几何，只修平台输入坐标与 scene 语义的对齐。
- 同步检查 label 绘制分支： [NoteMaster_Ver_1/Shared/Fretboard/FretboardLabelsLayer.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardLabelsLayer.swift) 已经根据 `context.ctm.d < 0` 做文本正向适配。修复后应稳定走翻转分支，如有文字朝向偏差，只在这里微调 Core Text 适配，不再反改 scene。

### 3. 补回归验证并清理定位日志

- 在 [NoteMaster_Ver_1/Shared/Fretboard/FretboardValidation.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardValidation.swift) 补一层“坐标变换后命中仍与可见 cell 一致”的回归思路：优先提炼纯函数级 helper 做断言，其次至少补强手工清单，明确验证 `vertical` 顶部/底部点击不会反向。
- 保留现有 manual checklist 里的 `vertical 为“左低右高、上空弦下高品、文字正立”`，并补一句 macOS 侧要验证“修复后点击可见空弦区/高品区仍命中同一格子”。
- 在修复确认后移除当前加在 [NoteMaster_Ver_1/Platform/macOS/macOSFretboardView.swift](NoteMaster_Ver_1/Platform/macOS/macOSFretboardView.swift) 和 [NoteMaster_Ver_1/Shared/Fretboard/FretboardBoardLayer.swift](NoteMaster_Ver_1/Shared/Fretboard/FretboardBoardLayer.swift) 的临时 `[VerticalFretboard][macOS]` 诊断日志，避免调试输出长期留在运行时链路中。

## 关键代码锚点

- 渲染对照：`macOSStaffView.applyState()` 已有 `contextNormalizationMode = .flipYToTopLeft`；fretboard 计划复用同一架构，而不是在 geometry 里写平台分支。
- shared 契约：`VerticalFretboardGeometryStrategy.makeScene(...)` 里 `y = drawingRect.minY + fret * displaySlotHeight`，以及 `FretboardValidation.validateAxisOrientation(...)` 对 `vertical` 的断言，说明 shared 语义已经明确。
- 平台缺口：`macOSFretboardView.handleRawMouseEvent(...)` 当前还在把未归一化的 view 坐标直接送进 `geometry.hitTest(...)`，这是修复 draw 后必须同步收口的命中边界。

## 预期结果

- macOS `vertical` 指板恢复为“上空弦下高品、文字正立”。
- 修复后点击顶部/底部可见格子时，命中结果继续与视觉一致，不会出现“画正了但点反了”。
- horizontal 模式行为保持不变，shared vertical scene/validation 无需推倒重来。
