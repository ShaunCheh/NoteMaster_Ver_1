# 方案3 分阶段计划

## 目标

- 打开设置面板时，页面左上角的 `settingsButton` 真隐藏，而不是仅被遮罩层盖住。
- 在设置卡片右上角增加一个与现有入口按钮同等级的圆形关闭按钮，点击后复用现有 `onDismissRequest -> setSettingsPresented(false)` 关闭链路。
- 保持 shared settings 内容层不变，不把“关闭面板”这种容器壳层行为塞进 [NoteMaster_Ver_1/Shared/Controls/SettingsPanelModel.swift](NoteMaster_Ver_1/Shared/Controls/SettingsPanelModel.swift) 或 [NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsPanelView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsPanelView.swift) / [NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsPanelView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsPanelView.swift)。

## 现状锚点

- [NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift](NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift) 和 [NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift](NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift) 的 `setSettingsPresented(_:)` 当前只做 `settingsContainerView.setPresented(presented)` 和 `updateSettingsButtonAppearance()`，没有隐藏页面齿轮。
- [NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsContainerView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsContainerView.swift) 与 [NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsContainerView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsContainerView.swift) 的 `cardView` 当前只有 `scrollView`，顶部没有 header；现有关键约束是 `scrollView.top == cardView.top + Style.cardContentInset`。
- 两个平台的 container 已经有统一的关闭回流：`onDismissRequest` 由背景点击触发，controller 侧已接到 `setSettingsPresented(false)`；关闭按钮应直接复用这条链路。

## 分阶段实施

### 阶段1：冻结职责边界

- 明确 controller 继续持有唯一展示状态真相 `isSettingsPresented`，只负责入口按钮显隐与将设置展示状态下发给 container。
- 明确 container 负责卡片壳层 UI：`backdrop`、`cardView`、新增 `headerView`、新增 `closeButton`、以及 dismiss 事件上抛。
- 明确 panel 继续只负责 model 驱动内容，不接入“关闭”按钮，避免污染共享 settings 内容组件。

### 阶段2：iOS 容器 header 化

- 在 [NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsContainerView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsContainerView.swift) 新增 `headerView` 和圆形 `UIButton closeButton`，位置固定在 `cardView` 内右上角。
- 保留 `cardView`、`scrollView`、`contentView`、`settingsPanelView` 现有层级，只把卡片改成“两段式”：`headerView` 在上，`scrollView` 在下。
- 将当前 `scrollView.topAnchor.constraint(equalTo: cardView.topAnchor, constant: Style.cardContentInset)` 替换为 `scrollView.topAnchor == headerView.bottomAnchor + headerSpacing`，其余左右/底部约束和 `scrollHeightMatchesContentConstraint` / `maximumScrollHeight` 逻辑继续沿用。
- 关闭按钮点击直接走 `onDismissRequest?()`；同时补 `accessibilityIdentifier` / `accessibilityLabel`，并让按钮尺寸、圆角、阴影等级与 controller 中的齿轮入口视觉一致。

### 阶段3：macOS 容器镜像 header 化

- 在 [NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsContainerView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsContainerView.swift) 对称增加 `headerView` 和圆形 `NSButton closeButton`。
- 同样将 `scrollView.topAnchor` 从 `cardView.topAnchor + inset` 改为 `headerView.bottomAnchor + headerSpacing`，并保留 `scrollView.height == settingsPanelView.height`（高优先级）与 `maximumScrollHeight` 上限。
- 关闭按钮复用现有 `onDismissRequest`；补 `toolTip` / 无障碍描述，避免与背景点击形成两套关闭链路。

### 阶段4：控制器入口按钮显隐同步

- 在 [NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift](NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift) 和 [NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift](NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift) 的 `setSettingsPresented(_:)` 中加入页面齿轮真隐藏逻辑：打开时隐藏、关闭时恢复。
- 保留 `updateSettingsButtonAppearance()` 作为“入口按钮可见时的样式同步”，不再依赖它表达“按钮消失”。
- 所有关闭入口统一回到 `setSettingsPresented(false)`：卡片右上角关闭按钮、背景点击、未来若需要 Esc/快捷键，也走这条状态真相链。

### 阶段5：验证与收尾

- 静态校验范围：
  - [NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift](NoteMaster_Ver_1/Platform/iOS/iOSViewController.swift)
  - [NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift](NoteMaster_Ver_1/Platform/macOS/macOSViewController.swift)
  - [NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsContainerView.swift](NoteMaster_Ver_1/Platform/iOS/Controls/iOSSettingsContainerView.swift)
  - [NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsContainerView.swift](NoteMaster_Ver_1/Platform/macOS/Controls/macOSSettingsContainerView.swift)
- 运行态手工回归重点：
  - 打开设置后：页面左上角齿轮消失，卡片右上角关闭按钮可见。
  - 通过关闭按钮和 backdrop 都能正常关闭，并恢复页面齿轮。
  - 首个 section/row 不被关闭按钮遮挡，卡片内容滚动上限仍正确。
  - `iOS` 旋转、`macOS` 窗口 resize 后，header 与 scrollView 约束稳定。
  - 连续多次打开/关闭不会留下错误层级、错误焦点或不可点击状态。

## 关键风险

- `scrollView` 现在的高度逻辑是基于内容高度和 `maximumScrollHeight`；加入 header 后，卡片总高度会上涨，需要确保 header 不把首行内容顶到关闭按钮下方。
- 如果关闭按钮只是 overlay 在 `scrollView` 上方而不做 header，首行 controls 很容易被遮挡；因此本计划坚持“header 在 scrollView 外”。
- 齿轮按钮要“真隐藏”而不是仅 `alpha = 0`，否则可能留下不可见但仍可聚焦/可点击的问题。
